Council Verdict

✔ Where the council agrees (4/5 independently)

  • The instrument can't see the proof yet. Eight of ten tasks sit at ceiling; aggregate pass@1's ±9-point CI structurally cannot certify anything. The only detectable event is the frontier task itself.
  • 0/5 is not zero. rotate's true pass rate could be as high as ~45%. It may be self-lane after all — which would dissolve the transfer-injection premise for it. Measure at n=100 before designing around "can't."
  • Pre-registration is mandatory. Success/fail thresholds committed to a file before training; results reported either way.
  • The near-duplicate laundering trap is the experiment's #1 failure mode — a mechanical ruler-collision filter plus nearest-neighbor disclosure is the price of any capability claim.

⚡ Where the council clashes

  • Sample size on the frontier task. Executor: n=20 (≥6/20, p≈0.01) keeps the run sheet tight. First Principles/Outsider: n=100 — a zero-background detector where ≥5/100 is decisive. Chairman sides with n=100: it costs under an hour of local sampling and can reroute the whole experiment.
  • Pause the overnight loop? Contrarian: snapshot + pause for attribution. Expansionist: let the flywheel spin. Resolved without pausing: the experiment trains on the curated pack only — the stockpile simply stays out of this run.

◎ Blind spots caught this round

  • The builder is a leakage channel (Outsider): aiming packs at the ruler's observed failures turns the test set into a dev set — the 10 tasks are partially burned. Mint and seal a ruler v2, selected blind to v1 results, after this experiment.
  • Nobody audits the tests (Outsider): weak corpus tests admit a wrong reference → training on confidently-wrong code. Extend mutation-adequacy to each injected task's test suite.
  • A flip alone proves nothing without a control (First Principles): an unrelated-family pack of identical size must NOT move rotate — otherwise "any training wobbles the ruler."

➜ The recommendation

Measurement before training, then one pre-registered single-variable frontier-flip run. Night 1: 3× baseline eval reruns (noise floor) + rotate n=100 / rle n=50 — if rotate >0/100 it's self-lane, stop and reroute. Night 2 (only if 0/100): ~150-pair rotate-family repair pack (corpus-origin tests, provenance triple on every pair, ruler-collision filter), one ORPO epoch on the pack alone, same q4_K_M quant back into Ollama, two post-eval runs. Success = rotate ≥5/100 twice, aggregate ≥0.84, no ceiling task below 4/5. A flip then earns the unrelated-family control before any capability claim — and afterwards, seal ruler v2.

The one thing to do first

Night 1 — pin the instrument, train nothing: rerun eval.py 3× on the unchanged baseline, then sample rotate at n=100 and rle at n=50. That single measurement either reroutes rotate to the self-lane or hands you a zero-background detector that makes the smallest possible training run provable. Full Advisor Responses

The Contrarian

Your ruler cannot see the thing you're about to chase. At 44/50, the entire measurable range is six samples, clustered in two tasks. Binomial SE at 0.88, n=50 is ~4.6 points — a single run can't distinguish 0.88 from anything below ~0.97. The noise floor was never measured: has eval.py ever been run twice on the same checkpoint at temp>0?

Smallest proving change is not an injection: (1) rerun the frozen ruler on the baseline for empirical variance; (2) raise n on the frozen tasks so rotate has resolution; (3) snapshot the corpus during the experiment — if the overnight loop keeps appending while you inject, you have two variables and zero attribution, and an unattended Ollama hiccup can stuff failures.jsonl with degenerate junk the retry loop will dutifully target.

The laundering trap: inject rotate-adjacent tasks, rotate flips, you call it generalization — null hypothesis: you trained a paraphrase of the ruler task and memorized the answer key. Pre-register an AST/n-gram similarity threshold before training; victory = movement replicates across two eval seeds AND zero regression on the eight ceiling tasks. DPO's likeliest outcome: rotate up, one 5/5 down — net zero, cherry-picked as a win.

The First Principles Thinker

"What moves the ruler" is the wrong question until you ask what the ruler can physically detect. Aggregate is fake resolution: eight of ten tasks at 5/5; you'd need ~+9 points to clear noise with ~12 available, nearly all from one task. The ruler's only detectable event is rotate.

But 0/5 is not zero — the 95% CI extends to ~45% true pass rate. So the smallest change is to the instrument: sample rotate at n=100 (frozen means no gradients, not no inference). Nonzero → rotate is self-lane and the injection premise weakens. 0/100 → a zero-background detector where a pre-registered ≥5/100 is significant (Fisher ~0.03).

Proof = specificity: two arms, identical pair count and steps — rotation-family vs unrelated-family reference. Capability is proven only if A moves rotate, B doesn't, and the saturated tasks hold. Report nearest-neighbor similarity or the result is uninterpretable. Pre-commit on negative: "one reference at this dose doesn't cross the task boundary" (next lever: dose-response), not "injection dead." And a one-task frontier can't certify a method — build a same-family probe set before scaling.

The Expansionist

If rotate flips, file it as the first execution of a template: ruler finds a 0/5 frontier task → targeted family pack → verified flip. Nothing in that loop is rotate-specific; rle is customer #2. The unit of progress becomes "frontier tasks flipped," and it compounds — each flip strengthens the overnight factory's actor, which re-mines failures.jsonl: the failure log turns from graveyard into frontier queue.

eval_history.jsonl is the sleeper asset: per-task, it's a longitudinal growth chart — families that move together reveal shared skill substrate and pick the next pack. When rotate flips, read the rest of the ruler: rle ticking up too = the pack taught a skill, not a task.

Cheap now: family tags on every task; a frontier ledger (task, family, pass-rate, first-flip checkpoint); nightly per-task eval rows with checkpoint hash. Upside: the ruler becomes the curriculum generator, and versioned sealed rulers become capability milestones.

The Outsider

Studying practices the skill; cheating practices the answer. It's cheating if any training task is a near-duplicate of an exam question — and as described, nobody checks that. Missing: an automated similarity audit printing each new training example's nearest exam match for a human to eyeball.

Subtler leak: the model never trains on the exam, but you read the exam and aim the pipeline at its failures. That turns the test set into a dev set — the human is the leakage channel; the 10 questions are partially burned. And who audits the tests? A weak suite lets a wrong imported solution in — training on confidently-wrong code is a bigger hole than hardcoding.

Statistics: 88% is 44 of 50 attempts; five tries per question is judging a shooter on five free throws. Smallest convincing experiment: pre-register; run rotate 100 times now (expect 0/100), train only on the new data, run 100 again. 0/100 → 60+/100 with the other nine holding, plus the nearest-training-example shown — a stranger believes that. Then retire these 10 and seal a fresh exam. Oversold: the crisp "88%" — fifty noisy coin flips wearing a lab coat.

The Executor

Family: rotate-class repairs (slice/modular-index/reversal). Data (~4h): filter MBPP+HumanEval by AST features → ~120 tasks; seed 2 mutations each → ~240 repair tasks; corpus tests = verifier; local K=8 routes each to self-lane (solvable) or transfer-lane (0/8: chosen = minimal-edit reference revert, rejected = top failing sample). Ship ≥150 pairs.

Guards: provenance triple {task_src, chosen_src, test_src}; hard-reject if model authored task and tests in-run; ruler-collision filter (5-gram Jaccard ≥0.35 or AST-hash match → reject, log). Stats: n=5 detects nothing — bump rotate+rle, re-baseline before training. Prereg (commit first): success = rotate flip with aggregate ≥0.84 and no saturated task <4/5; between = one repeat max.

Env: WSL2 Ubuntu 22.04, py3.11, cu121 torch, Unsloth ORPO 1 epoch, merge → GGUF q4_K_M → Ollama (same quant, like-for-like). Abort: <150 pairs post-guards; 2 training crashes; post-aggregate <0.80 → drop adapter, keep data. Wall-clock: ~7h — one overnight.
